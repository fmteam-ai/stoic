* Under `exit_policy = tp1_bank_runner` the **broker order now carries SL + TP2 from entry** (`bot_runner` → `execution`:
  `take_profit = tp_plan.tp2`, `original_take_profit = TP1`, `tp_plan` persisted). TP1 is a bot-side level: the bank fires when
  price reaches it; the broker can no longer close 100 % at TP1 before the bank runs. With the default `fixed_tp` the broker TP

  (TP2) — EA 1.65 ignores `new_sl`/`new_tp` on PARTIAL_CLOSE, so the follow-up is the only place they are applied; when the SL
  move is refused as a loosen the follow-up still moves the TP.

## #81 — GTP H4 history (unblocks the gold_trend_pulse shadow)
**Problem.** `engine.load_bars` built H4 by resampling the user's M15 doc (800 bars ≈ 50 H4 bars) while `H4_MIN_BARS = 200`,
so the daily bias was always "NONE — H4 warm-up 50/200" and GTP recorded no decisions. No XAUUSD H4 doc existed (EA 1.65
streams M15 + M1 only).

* **(a) Server-requested backfill — `backend/gold_h4_history.py`.** The poll-trades response carries
  `candles_request {symbol: XAUUSD, timeframe: H4, bars: 300}` for a terminal that (1) runs an EA with capability
  **`h4_history_v1` (EA ≥ 1.66)** and (2) streams XAUUSD M15, whenever the stored history is short (< 250 completed H4 bars),
  was never backfilled, or the last backfill is > 24 h old — i.e. at the first poll after start-up and then daily. A dropped
  response is re-asked after 10 min (`accounts.h4_history_request.dispatched_at`). The EA answers with
  `CopyRates(PERIOD_H4, shift 1 …)` (completed bars only) to the existing `/api/bridge/candles`; ingest accepts **400 bars** for
  H4/D1 within a **150-day** window, aligned to the **broker day grid** (`validate_bars(grid_offset_sec=offset)` — MT5 H4 bars
  open at broker 00/04/08…), stores them in `intraday_candles {symbol: XAUUSD, timeframe: H4}` and stamps `backfill_at`.
  Fail-soft: a lookup error never delays trade/modification dispatch. **1.65 terminals never receive the key** (and would
  ignore it); nothing else in the poll response changed.
* **Engine.** `load_bars` merges the stored EA H4 bars (doc ≤ 3 days old) with the M15 resample on the same broker grid
  (`merge_h4`: EA bars win on overlap, M15 fills the newest bars so the history never goes stale between daily backfills);
  `h4_source` = `ea_h4+m15` | `m15_resample`; `gtp_state` records `h4_bars` / `h4_source`.
* **(b)** `H4_MIN_BARS` stays **200**. Until the backfill lands the bias is `NONE` with the reason
  `H4 warm-up: n/200 completed H4 bars for EMA50 (m15_resample)`.
* **(c) Bot Health** → Risk State: **"GTP: H4 bars n/200"** for every config with GTP enabled — pass when warm (with the last
  EA backfill time), warn with the reason it is not progressing (terminal on EA 1.65 → "Update the EA to 1.66"; request in
  flight since …; will be requested on the next poll).
* **(d) Documented + shown in Bot Config** next to the GTP toggle (`gtp-replaces-engine-warning`): **enabling GTP on an account
  replaces that account's preset engine for XAUUSD** — gold is evaluated by the trend-pulse rules only; in shadow mode every
  gold cycle returns **HOLD** (decisions logged, no XAUUSD orders) until demo_live passes its gate; other symbols keep the
  preset engine (`ai_signals.analyze_symbol`, unchanged behaviour since v1.60.57). Guide §17 / FAQ updated.
* **EA 1.66** (`backend/static/EmergentTradingBridge.mq5`, `EA_CLIENT_VERSION "1.66"`, frontend `LATEST_EA_VERSION`):
  `ParseCandlesRequest` → `SendHistoryCandlesFor` only. Order send / close / partial close / fencing / heartbeat are
  byte-identical to 1.64/1.65 (`test_ea_1_65_candidate.py` hash pins still pass). Runbook: `docs/EA_1_66_RELEASE.md`.
  Capability table: `ea_capabilities.CAPABILITIES["h4_history_v1"] = (1, 66)`.
