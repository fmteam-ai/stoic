# Changelog

All notable operator-facing changes. Release tags: `vMAJOR.MINOR.PATCH` (signed CI releases).

## v1.60.9 — main115 review + A18 audit fix list (incl. main116 / A19 / main117 / A20 follow-ups)
- **A20-P1-03 / M117-1 host-profile timer** `stoic-host-profile.timer` now fires every **6 h** (+ ≤10 min jitter; `Persistent=` dropped — no effect on `OnUnitActiveSec`) against the unchanged 24 h maximum, so a daily window where the profile read as expired can no longer occur. The timer is a **host prerequisite**: `host_prereqs_missing()` reports a missing/inactive timer, so `deploy/update.sh` installs or repairs it on EVERY update (not only when the Docker fixes are missing); `host-prereqs.sh --check` evaluates it (exit 2 when missing), `doctor.sh` reports timer state, last-run failure and profile age. Readiness warns at **>12 h** (*refresh overdue*) and raises the `host_profile_refresh_overdue` ops alert; `host_profile_unverified` (critical) once expired/unsigned — both auto-resolve.
- **A20-P1-04 writer** `write_host_profile_file` returns non-zero on any mkdir/write/chmod/mv failure with path + error, removes the temp file and keeps the previous file; `host-profile-refresh.sh` exits 1 (systemd unit FAILED). `STOIC_HOST_PROFILE_DIR` overrides the target for tests.
- **A20-P2-01 crash dumps** agent **1.4** no longer sets the user-wide `Windows Error Reporting\Disabled=1` and removes it on upgrade; only the narrow per-user `LocalDumps\DumpCount=0` remains (best effort). `docs/VPS_AGENT.md`: dedicated Windows user for the agent + optional admin-only HKLM per-exe LocalDumps for `terminal64.exe` / `powershell.exe`.
- **M117-2 agent recovery** the durable read-back compares SHA-256 of the file bytes with the bytes written (`Test-StoicLedgerReadBack`), never a re-serialised JSON string; new `scripts/test_agent_recovery.ps1` (degraded → recovering → recovered, failure resets the window, tampered file detected) runs in CI under **Windows PowerShell 5.1** and locally under pwsh.
- **A20-P2-02 / M117-3 dashboard** the sign-in check has an 8 s deadline → outage screen with retry instead of INITIALIZING TERMINAL forever; anonymous visits redirect to /login after ONE request (no `/auth/refresh` round trip) thanks to a non-secret `stoic_session=1` hint cookie set/cleared with the session.
- **A20-P0-02 test #1** `production_reconcile.py --expect approved`: accounts/enabled/bots **and the exact account-id set come from the SIGNED policy** approved in Admin → Inventory (REFUSED when none approved / unapproved / expired; DEMO-only policy ⇒ every enabled account must be demo/paper). `deploy/update.sh` defaults `RECONCILE_EXPECT`/`RECONCILE_APPROVED_POLICY` to `approved`; an explicit `N/N/N` must still equal the approved policy. Acceptance checklist row 1 and the deploy checklists no longer name a fixed 6/3/3.
- **M117-6 workers** every worker container was *unhealthy* forever (the backend image's `/api/health` HEALTHCHECK, no HTTP in workers): workers now have a heartbeat-file health check (`workers.base.touch_heartbeat` every lease renewal / standby poll, `heartbeat_healthy` < 90 s) via the `x-worker-common` compose anchor; `compose ps` / doctor / `app_boot_failure` see real worker health.
- **M117-5 preflight** `clean_leftovers` no longer hides the `docker rm` error: for a dead container whose overlay `merged` dir is still mounted in the host namespace (dockerd's umount hit EBUSY — cPanel scanners / php-fpm / dovecot holding files inside the rootfs) it prints the holders (`fuser -vm`), lazy-unmounts the dir and retries the removal once; the final failure message names the permanent fix (exclude `/var/lib/docker` from imunify360/clamd/lfd/maldet).
- **M117-4 update.sh** hot-patched tracked files on the host (e.g. `deploy/*.sh` edited during a deploy jam) no longer abort the update after the backup with *"local changes would be overwritten by checkout"*: the edits are saved to `deploy/releases/local-changes-<ts>.patch` and discarded before `git checkout <tag>` (the deployed tree must equal the signed release). `deploy-production.yml` skips with a notice instead of failing when the opt-in `DEPLOY_*` secrets are absent.
- **M116-1 (process)** v1.60.8 points at main115 (contains the M115-1 update crash): mark the v1.60.8 GitHub release *"DO NOT DEPLOY — contains M115-1"*; tags are never moved or deleted. v1.60.9 is the first deployable tag.
- **A19-P1-04** signed host profile now lives in `deploy/state/host_profile.json` (read-only mount `/app/state`, read on every readiness check — no container restart); `deploy/host-profile-refresh.sh` re-detects daily via `stoic-host-profile.timer` (installed by `host-prereqs.sh`). Older than 24 h, future-dated (> 5 min skew) or unparseable ⇒ UNVERIFIED (blocks live, warns demo-only) with the reason shown.
- **A19-P1-03 / M116-4** degraded VPS agent ⇒ `CLOSE_ONLY` (`VPS_AGENT_DEGRADED`) for real-money / unattested accounts, `REDUCED` only for attested demo/paper. Agent recovery is a documented transition: durable ledger write (read-back equal) + 10-min stability window, status `agent_degraded` with detail *recovering* meanwhile. **M116-2** the agent re-probes the ledger save once per loop while degraded.
- **A19-P2-01** real-money wizard path defaults to manual MT5 login on the VPS (no stored password); the agent disables WER LocalDumps for its account (`Disable-StoicCrashDumps`); remaining in-memory exposure documented in the script.
- **M116-3** `check_deploy_python_snippets.py` also parses double-quoted `python3 -c "…"` snippets (32 snippets checked).
- **Security Audit #17** (docs/SECURITY_AUDIT_17.md): no P0–P2 in the main117/A20 delta; P3 hardenings — `production_reconcile.py --expect approved` REFUSES an approved policy without account ids (never counts-only) and the DEMO-only check uses the attested environment (`attested_environments_enabled`); `stoic_session` hint cookie accepted (constant, no secret).
- **Security Audit #16** (docs/SECURITY_AUDIT_16.md): SEC-001 (P2) degraded-agent policy now uses the server-authoritative `attested_environment` — a *declared* demo without admin attestation is real money ⇒ `CLOSE_ONLY` (was `REDUCED`); only PAPER / attested DEMO keeps `REDUCED`. Black-box preview and core-control regression sweep clean.
- **Security Audit #15** (docs/SECURITY_AUDIT_15.md): SEC-001 deploy-production workflow no longer expands branch/dispatch input inline in `run:` (env-bound; guard test over all workflows); host-profile HMAC uses length-prefixed canonicalisation; release-key pin refuses trust-on-first-use (fingerprint must be committed).
- **M115-1 (P0)** `record_host_profile`: HMAC values passed as argv (no f-string escapes — Python 3.6 safe), signing failure non-fatal (profile recorded unsigned + warning). Shell test runs it under `set -euo pipefail`; CI (`scripts/check_deploy_python_snippets.py`) parses every `python3 -c` snippet in `deploy/` with Python 3.6 syntax rules.
- **M115-2 + P1-03 (P1, live)** TRADING PAUSED is an execution gate: new authority domain `deploy_posture` → `canonical_decision` is CLOSE_ONLY while `platform_state.deploy_jam.trading_paused` is set **or the jam state is unreadable** (`DEPLOY_JAM_UNKNOWN`); worker-trading refuses new entries through the choke point, close/protect stay allowed. Readiness reports `unknown: true, ok: false` on a read error in production (advisory in demo/paper); the card shows `TRADING POSTURE · UNKNOWN`, never MANAGED.
- **M115-3 (P3)** host-profile HMAC uses a key derived from the ledger anchor key (HKDF-style, label `stoic-host-profile-v1`). Limit documented: root can re-sign — it stops accidental edits/drift, not a determined admin.
- **P1-04 (agent)** every `SecureStringToGlobalAllocUnicode` is paired with `ZeroFreeGlobalAllocUnicode` in `finally` (error paths included); the MT5 password is validated straight from the unmanaged copy, never held in a named variable or returned. Remaining exposure: the managed .NET string of a DPAPI-unprotected secret until GC (needed for the request body / ini write); `stoic-first-start.ini` is removed on success, error and reboot recovery.
- **P2-01 (agent)** `Save-StoicRestartLedger` failure ⇒ CRITICAL log, `agent_degraded` terminal status + `vps_agent_degraded` alert via heartbeat, **no automatic restarts** while degraded (probe at start); the infrastructure authority domain flags the terminal (`VPS_AGENT_DEGRADED`, REDUCED).
- **P2-02** AddAccountWizard resets form + policy on every open; policy is loading | known | unknown; REAL MONEY is disabled and "Policy unavailable" shown while unknown.
- **P0-01 (part)** `verify_ea_release.py --check` is offline: key from `RELEASE_PUBLIC_KEY_B64` or `--public-key`, fingerprint must equal `release/release_key.fingerprint`, never the runtime/bundle key. **P2-03** public status shows the signed release id + short commit (`release` block, `status-release-identity`).
- Not in this release (programme-level, tracked in PRD backlog): P0-01 single signed release envelope binding every artefact + full test evidence; P0-02 single signed canonical projection for every API/badge/chart, read-only audit role and seeded demo tenant; A18 "test #1" counts (needs the audit harness reference).

- **M114-7 (P3)** host profile is signed by the preflight (HMAC with the ledger anchor key, `STOIC_HOST_PROFILE_SIG`, `STOIC_HOST_DETECTED_AT`) and verified by the backend at read time — a hand-edited `dedicated` shows UNVERIFIED (blocks in production); `host_suitability` is now a PASS/FAIL pill on the Release Readiness card with the detection date.

## v1.60.7 — cPanel/RHEL-8 host prerequisites for existing installs · release-key pin · host suitability
- **deploy/host-prereqs.sh (new)** — idempotent, root-only: `fs.may_detach_mounts=1` (+ `/etc/sysctl.d/99-stoic-docker.conf`), docker root as SLAVE mount (`stoic-docker-root-slave` + `docker.service.d/10-stoic-private-root.conf`, one announced dockerd restart when needed), `host-mount-fix.sh --apply` drop-ins. PASS/FIX/WARN summary; non-zero exit only when (a)/(b) could not be applied. `bootstrap.sh` now calls it (one code path for install + update).
- **deploy/update.sh preflight** (before any build/pull/recreate): applies missing host prerequisites automatically (logged) or refuses with the one-line command under `--no-host-changes`; cleans leftovers of a previous jam (orphan overlay copies, dead/removing/created containers, `<12hex>_stoic-*` rename leftovers — never volumes); one `compose up`, on overlay EBUSY one cleanup + ONE retry, then a clear stop with the reboot recipe instead of a half-recreated stack (no auto-rollback into the same EBUSY).
- **deploy/restart.sh --env-changed / `make apply-env`** — the supported way to apply a `backend/.env` change (same preflight, recreate backend + workers). Plain `docker compose up -d` after an `.env` edit is documented as unsupported.
- **CI release public key** — `install.sh`/`update.sh`/`restart.sh` fetch `GET /public-key` from the public signer (`RELEASE_SIGNER_PUBLIC_URL`, default `https://stoic-signer.fly.dev`), require `key_id == RELEASE_SIGNER_KEY_ID`, show key + fingerprint, confirm (or `--yes`), write the pin; the local sidecar key is never pinned (N102-5). Backend: release purposes (`ea-release`, `model-manifest`) never fall back to the runtime/bundle key; readiness reports *"RELEASE_PUBLIC_KEY_B64 not pinned — … (run deploy/update.sh or see docs/RELEASE_SIGNER.md)"* instead of "signature does NOT verify"; the Release Readiness card on Bot Health shows the fix command.
- **Host suitability** — shared web host detection (cPanel/WHM, Plesk, DirectAdmin, httpd/exim/dovecot) in `doctor.sh` and the installer/update preflight (`STOIC_HOST_PROFILE`); production + non-demo-only ⇒ blocking readiness item, demo-only ⇒ warning.
- **Tests / CI** — unit tests for `verify_hex` (no release-purpose fallback, clear unpinned message); shell tests for the preflight branches with stubbed `docker`/`findmnt`/`sysctl`/`systemctl` (prereqs applied + idempotent, `--no-host-changes` refusal, leftovers cleaned, EBUSY retry once then stop, volumes never removed); `shellcheck` on deploy scripts in `static-analysis`.
- No change to trading logic, risk, PANIC or the security agent.
